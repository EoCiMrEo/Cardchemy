## Changes and reason

Added [a separate preparer](../../../scripts/prepare_private_query_vectors_v6.py)
and [keyless contracts](../../../backend/tests/test_private_query_vectors_v6.py)
for the twelve independently reviewed current private questions. Historical
eleven-case builder, source snapshots, frozen gold and vector packets were
not rewritten or used as substitutes.

- Exact gold/source byte pins and current-question roster pin; forged prepared
  objects, changed identities, authorization/publication/revision/page hashes
  and incompatible embedding spaces fail before dispatch.
- The default CLI does nothing; its optional input preflight reads only those
  private files and creates a current-question-only manifest in the same
  owner-private Temp directory. No settings or credential loader is present.
- The inert execution component requires a separate fresh fixed authorization
  plus matching process token and a central exclusive ledger claim. The claim
  prevents replay through a new output directory. The approved outer caller
  must still pin code/input and enforce resources; no execution CLI exists.
- A mocked native SDK request proved that even a single current question uses
  `:batchEmbedContents`, not `:embedContent`. The prospective manifest records
  that actual route, one question/vector per request, QUESTION_ANSWERING and
  1,536 dimensions; no lecture, prior turn or identity is sent.
- Prospective limits remain twelve calls, 512 estimated input tokens total,
  30 seconds/call, six minutes total, zero retries and USD 0.001 at a
  conservative USD 0.20/million input-token guard. These limits are preparation,
  not a provider authorization. Actual billing remains unknown; the native
  adapter reports estimated input tokens rather than a billing receipt.
- Each valid vector gets an exclusive private checkpoint. A provider or
  validation failure stops the attempt, retains valid checkpoints and reports
  aggregate uncertainty without printing responses, source text or exceptions.
