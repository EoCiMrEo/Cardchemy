## Changes

- `scripts/test_journey.py`: optional `--demo` builds the frontend into private
  temporary storage, runs the real journey and database proof, then holds the
  loopback application for 1–60 minutes. Default invocation still exits after
  verification. Ctrl+C, expiry and process failure use the existing cleanup.
- Temporary directories now have owner-only permissions before logs, database
  credentials or fixtures are written. Windows removes inherited permissions
  and Python-created explicit group/system entries, retaining only the current
  owner SID. The exclusive generated sign-in JSON is outside the served build
  root; the terminal prints its path and application URL, never credential values.
- Failure summaries report only process exit codes and fields from the shipped
  structured-log event/stage/error-code allowlists. Raw logs, arbitrary fields,
  exception text, tokens and private browser artifacts are discarded.
- `frontend/journey/vite.config.ts`: production-build output can be directed to
  private temporary storage; preview shares the same `/api` proxy and cookie
  rewrite as the existing development journey. `envDir: false` remains enforced.
- `docs/DEMO.md`: prerequisites, generated private sign-in file, authored PDF,
  instructor/student exploration, exact two-card deterministic-provider limits,
  expiry/cleanup and separation from packaged Nginx and human spoken-output checks.
- `backend/tests/test_demo_harness.py`: focused permission, stdout redaction,
  exclusive-file preservation and adversarial-log filtering contracts.

## Verification and limits

- Python compilation, CLI help and relevant `git diff --check` passed. Supplying
  `--demo-minutes` without `--demo` correctly rejects the command before services.
- Initial sandbox Docker access was denied; the harness cleaned up without
  printing credential values. Approved escalation was used only for uniquely
  named disposable loopback services and empty permission probes.
- The first production-preview journey timed out at generation completion.
  Its private workspace and containers were cleaned up. A subsequent diagnosed
  run passed the real Chromium journey (1 passed, 20.9 seconds) and final database
  proof, then entered the one-minute interactive period. No provider network
  request or production email delivery was made. The first timeout's exact cause
  is unconfirmed; it is recorded as a failed run rather than erased.
- Anonymous HTTP GET of `/demo-sign-in.json` returned only SPA HTML, with no
  credential JSON. On expiry the harness exited successfully. A separate check
  confirmed its exact temporary workspace, credentials, build and disposable
  journey containers were absent.
- After tightening the Windows explicit ACL entries, an empty temporary probe
  confirmed exactly one owner full-control entry, no inherited entries, and
  successful cleanup. The focused suite passed again: 3 passed in 0.74 seconds.

The complete frontend/backend/release gates are coordinated by the parent task.
Automated journey success does not establish real model quality, production
deployment, packaged Nginx behavior or spoken assistive-technology output.
